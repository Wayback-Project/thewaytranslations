## 2026-09-12 05:46 UTC — Proposed rule package: whole-Bible original-name restoration and metadata parity
- Context: A second-pass audit after the 2026-09-11 original-name consistency release found additional conventional person names, place names/cities, mixed restored/conventional forms, and reader-guide metadata gaps. The findings include Michael, Sodom/Gomorrah, several existing restored mappings that still have conventional occurrences, and a systematic `Beth`/`Beit` place-name consistency family.
- Proposer: Mike
- Rule statement: Approved restored-name decisions should be maintained as canonical editorial identity mappings, applied to Scripture only through reference-scoped reviewed edits, and accompanied by pronunciation/familiar-name alias metadata that downstream readers generate from the approved source. Do not use blanket string replacement or maintain separate competing translation text in reader applications.
- Detailed proposal: [Whole-Bible Original-Name Restoration & Reader Metadata Proposal](original-name-restoration/README.md)
- Rationale: The current release proved that reference-specific restoration with collision safeguards is workable, but the broader audit shows that relying on memory or a small fixed name list leaves inconsistent names and places behind. One auditable canonical process reduces drift and allows reader pronunciation/search features to stay aligned without becoming a second translation source.
- Status: proposed — editorial review required; no Scripture wording changed by this entry.
